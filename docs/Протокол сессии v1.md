# XR Session Protocol v1 — телефон ↔ очки

Командный протокол между смартфоном (владелец библиотеки пресетов, планировщик,
часы) и XR-очками (тонкий клиент: рендер + сенсоры). Версия протокола: `1`.

## 0. Принципы

1. **Телефон — authority.** Владеет библиотекой пресетов, пресет-часами,
   расписанием, решением «что показать». Очки ничего не решают.
2. **Очки — дисплей и сенсоры.** Рендерят слои из пушнутого манифеста,
   отдают дискретные жесты и позу головы. Никакого eye tracking, никакой
   динамической окклюзии — отказ от них является преимуществом по
   энергопотреблению и приватности, а не компромиссом.
3. **Жесты минимальны и фиксированы** (словарь v1, глобальный, не
   переназначается): `swipe_right` = следующий пресет (после последнего —
   закрыть), `swipe_left` = предыдущий пресет, `palm_hold` (~0.8 c) =
   закрыть текущий пресет, `pinch` зарезервирован. Жест по таймингу лишь
   сменяет или закрывает — богатого жестового языка нет.
4. **Control plane — JSON.** Читаемо, отлаживаемо, достаточно быстро для
   команд. Сырые потоки (поза) — те же JSON-сообщения, троттлинг на очках.
5. **Сырая камера не покидает очки.** Наружу уходят только поза головы,
   дискретные жесты и подтверждения.

## 1. Транспорт

- Первичный: **USB-C** (проводные очки типа XREAL Aura — топология протокола
  повторяет физическую топологию кита).
- Fallback: Wi-Fi Direct.
- Фрейминг: 4 байта little-endian (длина) + UTF-8 JSON. Одно сообщение —
  один JSON-объект с полем `type`.
- Heartbeat: очки шлют `heartbeat` каждые 5 c; телефон отвечает `ack`.
  Три пропущенных подряд — сессия считается оборванной, очки гасят контент.

## 2. Часы и синхронизация

Владелец времени — телефон. Все тайминги пресетов идут по телефонным часам.

- При установке сессии очки шлют `time_sync { t1 }` (t1 — часы очков, мс).
- Телефон отвечает `time_sync { t1, t2, t3 }` (t2 — приём, t3 — отправка
  по часам телефона).
- Очки вычисляют offset = ((t2 − t1) + (t3 − t4)) / 2, где t4 — приём ответа
  по часам очков, и дальше шлют события с обоими штампами:
  `t_glasses_ms` и `t_phone_ms` (= t_glasses_ms + offset).
- Повторная синхронизация — каждые 60 c или при дрейфе > 50 мс.
- Для аудита (будущий доменный профиль decision-intelligence-core) телефон
  штампует событие моментом получения по своим часам — задержка транспорта
  на проводе пренебрежима, на беспроводе фиксируется как известная погрешность.

## 3. Каталог сообщений

Каждое сообщение: `{ "type": ..., "msg_id": "uuid", ... }`.
На каждое сообщение, кроме `ack`/`heartbeat`, ожидается `ack { msg_id, status }`.

### 3.1. Телефон → очки (команды)

| type | поля | смысл |
|---|---|---|
| `manifest_push` | `preset_id`, `manifest` (объект по схеме xr-preset-manifest v2), `manifest_version` | Доставить/обновить пресет. Идемпотентно по паре (`preset_id`, `manifest_version`): повтор с той же версией — no-op, очки отвечают `ack{status:"duplicate"}`. |
| `preset_start` | `preset_id`, `start_at_phone_ms` | Запланировать старт пресета на пресет-часах. t=0 тайминга = `start_at_phone_ms`. |
| `preset_stop` | `preset_id`, `reason` (`gesture_close` \| `timeline_end` \| `phone_decision` \| `session_end`) | Остановить и погасить пресет. |
| `preset_switch` | `to_preset_id`, `at_phone_ms` | Немедленное переключение (решение телефона, напр. по данным decision core). Очки применяют `transition` из манифеста. |
| `ping` | — | Проверка живости вне heartbeat-цикла. |

### 3.2. Очки → телефон (события)

| type | поля | смысл |
|---|---|---|
| `gesture` | `gesture` (`swipe_right` \| `swipe_left` \| `palm_hold`), `t_glasses_ms`, `t_phone_ms` | Дискретное событие жеста. Никакого сырого стрима суставов — только классифицированный результат. |
| `pose` | `position` [x,y,z], `quaternion` [x,y,z,w], `t_glasses_ms`, `t_phone_ms` | Поза головы, троттлинг ~10 Гц. На телефоне по ней считается head-dwell (удержание направления 1.2–1.5 c) для антиспам-фильтра. |
| `state` | `preset_id`, `layer_states` [{`layer_id`, `state`}], `t_phone_ms` | Отчёт о состоянии: после `preset_start`, `preset_stop`, смены слоя. |
| `ack` | `msg_id`, `status` (`ok` \| `duplicate` \| `error`), `error`? | Подтверждение. |
| `time_sync` | `t1` | Запрос синхронизации (см. §2). |
| `heartbeat` | `t_phone_ms` | Живость сессии. |

## 4. Жизненный цикл сессии

```
очки подключаются → time_sync → телефон пушит библиотеку (manifest_push × N)
→ preset_start(preset_A, T0) → очки: state(preset_A, [Appear...])
→ pose-поток 10 Гц → телефон считает head-dwell
→ жест swipe_right в момент T0+8200 → очки: gesture{swipe_right}
→ телефон: preset_switch → preset_B (transition из манифеста)
→ жест palm_hold → очки: gesture{palm_hold}
→ телефон: preset_stop(preset_B, reason=gesture_close)
→ телефон пишет события в decision core (PresetServed, GestureInteraction, PresetClosed)
```

## 5. Семантика тайминга

- Пресет-часы: t=0 в `start_at_phone_ms`. Слои появляются/гаснут по
  `spawnAtMs` / `despawnAtMs` из манифеста; `fadeInMs`/`fadeOutMs` — дешёвые
  рампы прозрачности.
- Жест интерпретируется относительно текущей позиции в таймлайне, но
  действие всегда одно из двух: сменить или закрыть. Никаких
  контекстно-зависимых ветвлений жестов в v1.
- По окончании таймлайна — `timing.onEnd`: `loop` / `close` / `hold`.
- Очки кэшируют последние полученные манифесты: при обрыве сессии текущий
  пресет продолжает играть по своим часам до `durationMs`, затем гаснет
  (`onEnd=close`). Никакого «зависшего» контента.

## 6. Ошибки и переподключение

- `ack` с `status=error` содержит `error` (человекочитаемо) — телефон решает:
  повтор, пропуск пресета, разрыв сессии.
- `manifest_push` идемпотентен (см. §3.1) — безопасен при ретраях.
- Переподключение: очки шлют `time_sync`, затем `state` с текущим
  `preset_id` (если кэш жив) — телефон либо продолжает (`preset_start` с
  поправкой), либо останавливает.

## 7. Стык с decision-intelligence-core (следующий шаг, не часть v1)

Телефон как edge-узел эмитит события доменного профиля XR-рекламы:
`PresetServed`, `ImpressionValidated` (head-dwell ≥ порога), `GestureInteraction`,
`PresetClosed` — метрики с `evidence_refs` на on-device доказательства.
Инварианты ядра ложатся один в один: I3 — «нет доказательства внимания,
нет биллинга», I6 — «нет двойного биллинга при ретраях». Схема этих событий
и сам доменный профиль — отдельная работа после v1.

## 8. Приватность

Очки → телефон: поза головы + дискретные жесты + подтверждения. Сырое видео
и сырые суставы руки за пределы очков не выходят. Телефон → ядро/аудит:
агрегаты и доказательства, дальше — только хэши (паттерн Defense-Dossier).
